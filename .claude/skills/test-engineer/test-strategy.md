設計「$ARGUMENTS」的測試策略：

**測試層級:**

| 層級 | 範圍 | 數量 | 優先級 |
|------|------|------|--------|
| 單元測試 | Service 方法 | 多 | 高 |
| 整合測試 | DB + MinIO | 中 | 中 |
| API 測試 | 端點功能 | 少 | 高 |
| E2E 測試 | 完整流程 | 少 | 低 |

**測試金字塔:**
```
      /\
     /E2E\      <- 少量，驗證關鍵流程
    /──────\
   /  API   \   <- 驗證端點行為
  /──────────\
 / Integration \ <- 驗證元件互動
/────────────────\
|   Unit Tests   | <- 大量，快速回饋
```

**測試優先順序:**
1. 權限檢查 (安全性)
2. 成功案例 (Happy Path)
3. 錯誤處理 (Error Cases)
4. 邊界條件 (Edge Cases)

**測試環境:**
- 使用 Mock DB/MinIO
- 隔離測試資料
- 測試後清理

**覆蓋率目標:**
- 核心邏輯: 100%
- 錯誤處理: 80%+
- 邊界條件: 關鍵路徑
